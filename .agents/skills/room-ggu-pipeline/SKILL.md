# 룸꾸 기획·구현 파이프라인

프로젝트 루트의 `AGENTS.md`를 먼저 읽는다. 기존 기능과 사용자의 최신 지시를 유지한다.

1. **기획:** 변경의 입력·결과·완료 조건을 정한다. 구조나 흐름 설명이 필요하면 `../answer-me-with-html/SKILL.md`를 읽고 동봉 CLI로 `docs/`의 기획 원고를 HTML로 만든다. 단순 수정에는 기획 페이지를 추가하지 않는다.
2. **구현:** 검증 가능한 한 덩어리씩 구현한다. 문장 해석은 `src/app/planner.js`, 상태 변경은 `src/app/ops.js`, 모델 응답 합치기는 `src/app/model-turn.js`에 둔다. 방·치수·충돌·저장 계산은 AI와 분리한다. 설명, 추정값, 직접 설정값의 출처를 유지한다.
3. **디자인:** 화면 작업에는 `../unslop/SKILL.md`와 관련 참조만 읽는다. `docs/design-direction.md`의 방향(종이 위 실내 모형과 줄자, 먹 중립색, 줄자 노랑은 직접 정한 치수에만)에 맞춰 간격, 색, Lucide 아이콘, 문구, 글꼴, 레이아웃, 3D 표현, 상호작용을 점검한다. 시각적 중심은 화면 전체의 편집 가능한 방이고, 대화 시트와 입력창이 사용 방식의 중심이다. 새 도구는 탭이나 메뉴가 아니라 `src/ui/surfaces.jsx` 컴포넌트와 `SURFACE_KINDS` 항목으로 추가한다. 로딩·추론·오류·빈 화면·선택 상태를 함께 디자인한다.
4. **문구:** `../humanizer/SKILL.md`로 새 UI·오류·안내 문구를 검토한다. 한국어로 짧고 구체적으로 쓰며, AI 기능이나 추정 정확도를 과장하지 않는다. 상태 메시지에 개발 프레임워크 이름을 불필요하게 넣지 않는다.
5. **검증:** `npm run verify`를 실행한다. UI·상태 동작 변경에는 `npm run test:e2e`로 브라우저 회귀 테스트도 실행하고, 데스크톱과 모바일에서 실제로 조작한 화면을 확인한다(입력창이 가려지지 않는지 포함). AI 경로를 바꿨다면 실제 모델 로딩·추론 또는 그 검증 한계를 기록한다. 결과는 `docs/verification.md`에 남긴다.
6. **반영:** 검증한 변경만 커밋·푸시한다. GitHub Actions 완료를 확인하고, 공개 주소의 `version.json` 커밋이 최신인지와 핵심 흐름이 동작하는지 확인한다. 미완료 검증을 통과했다고 적지 않는다.

Codex는 `$room-ggu-pipeline`, Claude Code는 `/room-ggu-pipeline`으로 이 절차를 호출한다. 자동 스케줄러나 무한 반복 프로세스를 만들지는 않는다.
