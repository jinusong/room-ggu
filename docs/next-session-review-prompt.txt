팀원 의견과 사용자 요청

1. “실제 크기 가늠이 안 돼서 내 키 말하면 아바타라도 띄워주고.”
   내 키와 가구를 같은 축척으로 비교할 수 있어야 한다. 키는 선택 입력이고 기본 키와 사용자 입력의 출처가 구별되어야 한다.
2. “가구에 앉은 모습”, “침대에 누워 있는 모습”.
   의자·소파·라운지체어·벤치에 앉기, 침대에 눕기가 실제 놓인 가구에 연결되어야 한다. 가구 크기·위치·회전을 바꾸고 방을 전환해도 참조와 자세가 올바르게 유지되어야 한다.
3. “원룸 자취방은 화장실도 구현할 수 있어야”, “사각형 집만 남는 건 아닐 듯”.
   방마다 분리된 화면 외에 화장실을 포함한 집 전체를 보고, 공간을 연결해 ㄱ자 같은 집 외곽을 구성할 수 있어야 한다.
4. 추가 요청: “집 전체도 화장실 포함해서 3D로 볼 수 있게”.
   집 전체 2D와 3D가 같은 배치를 사용하고, 화장실·방별 가구·아바타가 실제 위치와 크기로 함께 보여야 한다. 3D에서 돌려보기·공간 선택·방 편집 진입·PNG 저장도 동작해야 한다.

현재 구현의 출발점

- 키 아바타(80~230cm), 서기·앉기·눕기, 집 전체 2D/3D, 화장실 붙이기, 공간 드래그·벽 스냅, 방별 가구 편집이 있다. 저장 형식은 v4이고 v1~v3를 읽는다.
- 단일 3D 렌더러를 방별·집 전체 보기에서 함께 사용한다. 집 전체의 내부 벽은 낮춘 단면이고 연결 문·변기·세면대·샤워 공간은 위치 비교용 초안이다. 신체 비율과 착석 높이도 단순 모형이다.
- 명시적 키·집 전체 보기 명령은 앱이 처리하고, 나머지 상담은 모델 우선 해석을 유지한다. 자동 브라우저 테스트의 ?model=off 결과와 실제 모델 검증 범위는 docs/verification.md에서 구별한다.
- 구현되어 있다는 설명을 그대로 결론으로 삼지 말고, 위 네 요구가 실제 사용 흐름에서 완료되는지 직접 재현해 판단해줘.

작업 순서와 완료 기준

1. 의견별로 현재 동작·재현 절차·증거·불편 또는 오류·수정 우선순위를 정리해줘. 기능이 보이는지만 확인하지 말고, 처음 쓰는 사람이 도구를 발견하고 원하는 결과까지 도달하는지 확인해줘.
2. 디자인을 실제 화면에서 점검해줘. 기존의 종이 위 실내 모형·먹 중립색·줄자 칩 방향을 유지하면서, 방/집 전체 구분, 2D/3D 전환, 선택한 공간, 아바타·자세 도구, 라벨 겹침, 치수 가독성, 모바일 시트·입력창·터치 영역을 개선해줘. 도구는 기존 대화 시트와 + 흐름에 연결해줘.
3. 기능 오류를 재현해 우선 수정해줘. 특히 가구와 아바타의 실제 축척, 앉기·눕기의 위치·회전·침대 길이 안내, 방 전환·삭제 후 참조, 집 전체 모든 보기에서 아바타 표시의 일관성, 2D/3D 공간·설비 좌표 일치, 공유 벽·문 중복, ㄱ자·여러 공간·음수 좌표, 카메라 자동 맞춤과 사용자 시점 유지, 3D 선택 후 방 편집, 현재 보이는 화면의 PNG를 확인해줘.
4. 저장·새로고침·JSON 왕복·실행 취소/다시 실행 후 방별 가구와 키·자세·공간 위치·보기 설정을 보존하는지 확인해줘. 기존 배치 파일을 깨뜨리지 말고, 사용자가 직접 입력한 치수를 모델이나 크기 초안이 덮어쓰지 않게 해줘.
5. 실제 브라우저에서 데스크톱 1440×900, 모바일 390×844와 320×640을 조작해줘. WebGL과 localStorage가 막혔을 때도 2D·대화·배치 흐름을 확인해줘. npm run verify, npm run test:e2e, npm run format:check와 필요한 의미 있는 회귀 테스트를 실행하고 화면을 확인해줘.
6. AI 경로를 바꾸면 실제 Gemma·SigLIP의 해당 흐름도 확인해줘. 실행할 수 없는 모델·기기·실제 휴대폰 키보드 등은 미검증 범위를 구체적으로 적어줘. 모델을 끈 테스트만으로 실제 AI 검증이 끝났다고 쓰지 말아줘.
7. 제안 목록으로 끝내지 말고 재현한 문제를 코드와 UI에서 수정해줘. 검증 기록·필요한 공용 규칙과 안내를 갱신한 뒤, 승인된 Git 작업 규칙에 따라 검증된 변경을 커밋·푸시해줘. 배포 워크플로와 공개 version.json의 커밋, 공개 사이트 핵심 흐름을 확인해줘. 새 채팅이나 자동화는 만들지 말아줘.

마지막에는 의견별 반영 상태, 이번에 고친 것, 실제로 통과한 검증, 남은 한계, 배포 주소·버전·커밋을 짧게 알려줘. 리뷰와 수정은 사실과 재현 결과를 근거로 진행해줘.
