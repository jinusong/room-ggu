# 검증 기록 · 2026-11-13

## v5.1 모델 우선 해석과 실제 사진 평가

요청: 실제 사진으로 사진 모델 정확도를 재고, 규칙은 대체 경로로 두고 기본은 모델이 해석하게 한다.

### 실제 사진 정확도 (`eval/photo/`)

- **사진:** Openverse(Flickr·StockSnap·rawpixel 등)와 Wikimedia Commons에서 CC 라이선스 사진 후보 약 750장을 받아, 가구가 주인공인 사진을 사람이 직접 보고 20종마다 5~6장, 모두 118장을 골랐다(제품 사진 79장, 다른 가구가 함께 있는 방 사진 39장). 정답은 고른 사람이 정했다. 종류마다 반씩 무작위로 나눠 dev 60장은 모델·질문·기준값을 고르는 데만 쓰고, test 58장은 마지막에 한 번만 쟀다. 사진 파일은 저장소에 넣지 않고 주소·작성자·라이선스를 `manifest.json`에 남겼다.
- **실행:** 앱의 사진 경로(`imageData` → Worker)를 Mac Chrome(WebGPU, shader-f16)에서 그대로 실행했다. 채점은 앱과 같은 함수를 쓴다.
- **기준선(배포 중이던 2792c0c):** SmolVLM 256M 설명 + 규칙 단어 찾기. test 58장 중 맞는 종류로 초안 29.3%, 틀린 종류로 초안 17.2%, 종류 못 찾음 19.0%, 설명을 버림 34.5%(“Bed.”처럼 한 단어 답도 버리던 필터 문제 포함). 전체 118장은 25.4%.
- **dev에서 비교한 것:** SmolVLM에 보기 목록에서 고르게 하면 15%로 더 나빠졌다(앞쪽 보기 sofa·bed만 반복). 설명 질문을 바꿔도 33~37%. CLIP ViT-B/32 68.3%, SigLIP base 80~85%. SigLIP 4비트(q4f16) 81.7%·상위 3개 98.3%로 크기 대비 가장 나아 채택했다. 초안을 바로 만들 기준 확률 0.7도 dev에서 정했다.
- **최종(SigLIP, test 58장):**

| 실행 방식 | 1순위 정답 | 상위 3개 안 | 초안 맞음 | 초안 틀림 | 후보에서 고름 | 후보에 없음 | 사진 1장 |
|---|---|---|---|---|---|---|---|
| GPU, q4f16 약 150MB | 82.8% | 96.6% | 72.4% | 6.9% | 19.0% | 1.7% | 약 65ms |
| CPU, q8 약 210MB | 84.5% | 94.8% | 81.0% | 1.7% | 12.1% | 5.2% | 약 4.6초 |

- 틀린 경우는 대부분 비슷한 가구끼리다. 장식장·옷장을 수납장으로, TV장을 수납장으로, 소파테이블이 앞에 있는 거실 사진을 소파테이블로 봤다. 사진만으로 cm를 재지 않으며 크기는 유형 기본값이다.
- 한계: 118장은 작은 표본이고 사람이 고른 “가구가 잘 보이는” 사진이다. 휴대폰으로 찍은 어두운 사진·여러 가구가 겹친 사진은 더 나쁠 수 있다. 한국 가구 쇼핑몰 사진으로는 재지 않았다.

### 모델 우선 해석

- 사이트를 열면 WebGPU가 있으면 Gemma 3 1B를 자동으로 준비한다. 준비되면 모든 문장을 모델이 먼저 해석하고(JSON 스키마 제약), `src/app/interpret.js`가 숫자·이름·말하지 않은 속성·문장에 없는 동작을 검증한다. 준비 중·꺼짐·미지원·25초 초과·형식 오류면 규칙이 처리하고 이유를 턴에 적는다.
- **실제 Gemma, 같은 대화 18문장(`eval/chat/`)**, 턴당 1.8~2.7초:
  - 1차(검증 보강 전): 모델 혼자 맞힌 것은 크기 느낌·깊이·색·놓기·회전·책상 치수 등 9개 정도. “빈 방으로 시작할래”를 소파 초안으로, “되돌려줘”·“공간 목록 보여줘”·“겹친 가구 정리해줘”를 놓침. “배치를 파일로 저장하고 싶어”에서 “배치”를 놓기로 읽어 책상을 방에 놓음. 내 코드의 벽 색 검증 버그와 “하나 놓고 싶어”를 새 가구로 보지 못한 문제도 찾음.
  - 수정: 문장에 명령(되돌려·저장·공간 목록·빈 방 등)이 분명하면 모델 선택 대신 명령을 따르고 바로잡은 내용에 남김. 놓기 동작은 “놓아/놔 줘/배치해” 같은 동사가 있을 때만. 벽 색 검증 버그 수정. 방 이야기(“~방으로 꾸며줘”) 판별을 검증에 추가.
  - 최종: 18문장 중 16개가 기대한 결과. 모델이 혼자 맞힌 문장 6개(따뜻한 벽 → 샌드, 2인 낮은 소파 170·높이 65, 깊은 좌석 100, 네이비, 놓기, 90도 회전), 앱이 바로잡아 맞게 처리한 문장 10개(명령 6개, 문장의 이름·숫자에 맞춘 4개). 다르게 처리된 2개: “책 읽는 아담한 방으로 꾸며줘”에서 공간 유형이 서재로 바뀌지 않고 천장만 바뀜, “푹 기대 앉을 만한 거”를 라운지체어가 아닌 소파로 잡음.
  - 결론: 1B 모델은 크기 느낌·색·이어지는 수정은 잘 읽지만 명령형 문장의 의도는 자주 놓친다. 그래서 명령어가 분명한 문장은 앱이 바로잡는다. 더 큰 모델을 쓰면 나아질 수 있지만 내려받는 크기가 커서 이번에는 바꾸지 않았다.
- 화면: 답 아래에 “Gemma가 해석 · 앱이 숫자·범위 확인”, 바로잡았으면 “앱이 2곳 바로잡음”(눌러서 내용 확인), 규칙이면 “상담 모델 준비 중이라 규칙으로 처리”. 입력창 아래 상태줄에 모델 준비 진행률·끄기·켜기. 해석 중에는 그 턴에 “문장을 해석하는 중”과 멈추기.
- 사진: 사진만 보내면 사진 판별을 자동으로 실행한다. 실제 CC0 사진으로 UI에서 확인: 소파테이블 사진은 96%로 초안과 다른 후보 칩, 의자 사진은 46%로 초안 없이 후보 3개(`docs/screenshots/photo.png`, `mobile-photo.png`). “식탁였나요”처럼 조사가 틀린 문구를 찾아 고침.

### 자동 검증

- `npm run verify`: 단위 테스트 49개(모델 해석 검증 10개 포함), 문법, 정적 빌드 통과. `npm run format:check` 통과.
- `npm run test:e2e`: 10개 통과. 브라우저 테스트는 `?model=off`로 규칙 경로를 확인하고, 상태줄 “모델 꺼 둠 · 규칙으로 답해요”와 턴 표시 “상담 모델을 꺼 둬서 규칙으로 처리”를 검사한다. CI(Chromium, WebGPU 없음)는 같은 규칙 경로다.
- 데스크톱 1440×900·모바일 390×844에서 모델이 켜진 상태로 조작: 가로 넘침 없음, 콘솔 오류 0개.

### 남은 확인 범위

- 모델 우선 경로는 Mac Chrome 한 기기에서만 실제 모델로 확인했다. Qwen3 0.6B(f16 미지원 GPU) 경로, Android Chrome, Windows GPU는 확인하지 않았다.
- 실제 휴대폰 가상 키보드, Safari·Firefox는 여전히 확인하지 않았다.

## v5 대화 시트·방 모형 전면 재설계 · 2026-11-12

화면 구조·색·글꼴·로고·아이콘·컴포넌트를 새로 만들었다. 기존 계산(카탈로그·저장 검증·충돌·치수 해석)은 유지하고, 문장 해석(`src/app/planner.js`)·상태 연산(`src/app/ops.js`)·모델 합치기(`src/app/model-turn.js`)를 나눴다.

### 자동 검증

- `npm run verify`: 공용 스킬 4개 연결, 소스 문법(esbuild로 JSX 포함), 단위 테스트 39개, 정적 빌드 통과. `npm run format:check` 통과.
- `npm run test:e2e`: Chrome 브라우저 테스트 10개 통과. 확인한 흐름:
  - 첫 화면 대화 중심(시트 폭 380px 이상·높이 800px 이상, 시작 질문, 도구 없음) → 방 설명 → 방 크기 도구 → 입력 즉시 반영 → 마감 비교 도구, 이전 도구 접힘
  - 가구 설명 → 치수 직접 입력 도구(가로 200·깊이 85는 노란 줄자, 높이는 점선) → 점선 초안 → 놓기 → 같은 도구가 놓인 가구로 이어짐 → 회전·삭제·되돌리기 → 새로고침 후 배치와 대화 복원 → JSON 저장
  - 선택한 가구가 입력창 대상이 되어 “가로 140cm로”, “초록색으로”가 그 가구에 적용되고, “침대도 하나 더”는 책상을 바꾸지 않고 새 초안을 만듦
  - 가구 20종·썸네일 20개·검색·규격 선택(6인 식탁 180×90×74)·러그 배치
  - 방 크기 입력 중 반영과 한 번의 되돌리기, 유형 변경 시 직접 정한 가로 유지, 크기 초안, 바닥 마감
  - 대화로 방 변경·서재 추가·공간 전환 후에도 대화가 이어지고 공간마다 가구 보존, 다른 공간 도구 표시
  - 공간 추가·삭제·되돌리기, 잘못된 배치 파일 거절과 정상 파일 복원
  - 2D로 저장 후 다시 열어 3D에서 가구 끌기, 2D에서 가구 끌기
  - 모바일 390×844: 대화로 시작, 시트 전체·낮게·절반 전환 중 입력 중인 글 유지와 입력창 화면 안 유지, 놓기 후 도구 막대와 대화 유지, 390·320px 가로 넘침 없음
- WebGL과 저장소를 막은 Chrome에서 2D로 열리고 “3D를 준비하지 못해 2D 평면으로 열었어요”, “자동 저장 불가”를 안내. 대화·초안·놓기 동작, 가구 고르기는 썸네일 대신 아이콘으로 표시. 페이지 오류 0개.
- 데스크톱 1440×900과 모바일 390×844 화면을 직접 캡처해 확인했다(`docs/screenshots/`). 콘솔 오류 0개.

### 실제 모델

Mac Chrome(헤드 모드, WebGPU adapter와 shader-f16 제공)에서 로컬 프로덕션 빌드로 확인했다.

- **Gemma 3 1B** (`gemma3-1b-it-q4f16_1-MLC`) 내려받기·로딩·한국어 응답 확인. 응답 시간 약 0.9~1.8초.
- 1차 실행에서 찾은 문제와 수정:
  - “벽은 세이지로 바꿔줘”에 모델이 `ui: types`를 골라 마감 도구가 공간 유형 도구로 바뀜 → 요청 단어로 규칙이 확신한 도구는 유지하고 모델 선택은 칩으로만 제안
  - 모델이 “벽은 세이지로 바꿔주세요”처럼 사용자 문장을 되풀이 → 6글자 이상 되풀이한 답은 쓰지 않음
  - “앉는 부분이 깊었으면”을 규칙·모델 모두 놓침 → 깊은 좌석 단서 보강
  - 소파 초안이 있을 때 “책 읽는 아담한 방으로 꾸며줘”가 가구 상담으로 감 → 방 이야기 판별 추가
  - 조절된 치수를 “유형별 기본값”이라고 답함 → 출처에 맞는 문장으로 수정
- 2차 실행: 마감 도구 유지(“도구는 규칙대로 유지” 표시), 세 명·낮은 소파는 가로 220(규칙)·높이 65(모델 단서), 깊은 좌석 100cm, 방 이야기는 방 크기 도구, “소파 색상은 네이비로”는 색상 도구 유지. 이때 모델이 “1인용의 소파로 가늠해볼게요”라는 프롬프트 예시 문장을 그대로 냄 → 예시 문장을 베끼거나 말하지 않은 인원수를 말하는 답은 버리도록 수정.
- 3차(최종 빌드): 위 다섯 문장 모두 기대한 도구와 치수. 모델 답 중 “깊이를 알면 더 정확하게 알려드릴 수 있어요.”만 화면에 남고 나머지는 걸러짐. “예시 방 불러오기”가 파일 도구로 가던 문제를 발견해 수정.
- **SmolVLM 256M** (q4, WebGPU): 실제 다운로드·추론 확인. 앱 3D 렌더에서 잘라낸 소파 이미지(합성 이미지, 440×300px)를 “Couch, shape, color, visible seating.”으로 설명해 소파 초안을 만듦. 같은 소파를 작은 썸네일로 넣었을 때는 “The chair is a light grey color.”(의자로 잘못 인식), 또 한 번은 숫자만 반복하는 설명을 냄 → 읽을 수 없는 설명은 보여주지 않고 종류를 직접 고르게 안내. 사진 모델을 올리면 상담 모델은 내려지고 화면에 그 상태가 표시됨.
- 실제 사진으로 정확도를 다시 재지는 않았다. 작은 모델은 모든 문장·사진에서 맞는 도구나 종류를 보장하지 않는다. 잘못 고르면 사용자가 칩·`+` 메뉴·종류 칩으로 바로 바꿀 수 있다.

### 남은 확인 범위

- 실제 휴대폰의 가상 키보드는 확인하지 못했다. visualViewport 높이에 맞추는 코드와 390·320px 레이아웃만 브라우저에서 확인했다.
- Safari·Firefox·여러 GPU는 확인하지 않았다.
- 외부 서비스의 비공개 구현을 분석하지 않았고, Google Cloud·A2UI·Vercel AI SDK 공개 문서만 참고했다.

## v4 채팅 중심·생성형 UI 리디자인

- `npm run verify`: 공용 스킬 연결, JavaScript 구문, 단위 테스트 23개와 정적 빌드 통과. `npm run format:check` 확인.
- `npm run test:e2e`: Chrome 브라우저 테스트 10개 통과. 첫 화면에서 상담·넓은 채팅 영역·고정 입력창 접근, 대화별 동적 카드, 카드에서 치수·색상 변경과 도면 동기화, 가구 배치 후 대화 유지, 모바일 상담↔도면 전환과 작성 중 입력 보존을 검증.
- 기존 방·가구·다중 공간·JSON·3D 드래그·실행 취소 회귀 흐름도 통과. 카드 선택 검증은 모델 호출을 대체하지 않는 단위·기능 검사임.
- 실제 Gemma 3 1B 로딩·추론 확인. 벽 색상 요청에서 `ui: finishes`, 2인 소파 요청에서 `ui: sizes`를 반환하고 화면에 “AI가 고른 편집 도구”와 해당 조작 카드가 표시됨.
- 실제 모델이 벽 색상 요청에 `kitchen/large`를 함께 제안하는 것을 관찰. 요청 문맥에 따라 허용되는 속성을 제한해, 다시 실행했을 때 기존 원룸 4 × 4 × 2.4m는 보존하고 벽만 세이지로 변경됨을 확인. 소파 요청에 언급되지 않은 낮은 높이 제안도 걸러내는 회귀 테스트 추가.

## 남은 환경별 확인 범위

모든 모바일 기기·Safari·Firefox·GPU를 검증한 것은 아닙니다. GPU/메모리 부족 시 AI 모델 준비가 실패할 수 있고, 사진 CPU 모드는 기기에 따라 느립니다. 직접 입력·규칙 기반 상담·2D 배치는 별도 모델 없이 작동합니다.

GPU·WebGL·로컬 저장소를 차단한 별도 브라우저 컨텍스트에서도 2D로 열리고 자동 저장 불가 상태를 안내하는 것을 확인했습니다.

실제 네트워크 기록에서 ONNX WASM은 버전이 고정된 jsDelivr 주소로 로드됨을 확인해, 빌드에 중복 포함되던 미사용 26MB WASM 파일을 배포물에서 제외했습니다. 제외 후 사진 추론도 재확인했습니다.
