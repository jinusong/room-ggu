# 룸꾸 디자인 방향

- 제품: 방과 가구를 이야기하면 편집 도구가 대화에 나타나고 실제 도면에 연결되는 인테리어 웹.
- 성격: 차분하고 구체적인 작업 대화.
- 세계: 흰 상담 테이블, 옆에 펼친 실내 모형, 얇은 도면 선과 무광 목재.
- 중심 장면: 대화 안에서 바뀌는 치수·마감·가구 규격 카드와 옆의 실시간 3D 공간.
- 고유한 디테일: 편집 카드의 값과 도면이 같은 상태를 공유하며, AI가 고른 도구와 기본 상담 도구를 구분한다.

## 화면과 상호작용

기본 화면과 첫 메뉴는 상담이다. 데스크톱에서는 넓은 대화 영역과 고정 입력창이 주 화면이며 오른쪽에 2D·3D 미리보기를 둔다. 공간 설정·가구 찾기·목록은 보조 도구다. 상담 중에는 별도의 오른쪽 치수 패널을 중복 표시하지 않는다.

빈 화면에 기본 소파 치수 폼을 먼저 보여주지 않는다. 사용자가 시작점을 고르거나 말하면 현재 작업에 필요한 카드 한 개가 나타난다. 방은 치수·유형·마감, 가구는 치수·규격·색상 카드 중 선택한다. 다른 도구로 바꾸거나 상세 값을 직접 고칠 수 있다.

대화 기록은 스크롤되고 입력창은 하단에 남는다. 가구를 방에 놓은 뒤에도 대화가 이어진다. 사진은 입력창의 첨부 버튼이나 드롭으로 추가하며 필요할 때만 미리보기와 분석 버튼을 보인다.

모바일은 상담을 펼쳐 시작한다. 도면 보기와 상담 복귀를 명시적인 버튼으로 연결한다. 공간·가구 보조 도구도 같은 메뉴에서 접근한다.

## 시각 기준

기존 룸꾸 이름과 집 모양 로고, 세이지 색상을 유지한다. 내비게이션은 조용하게 두고 채팅 본문·질문·입력창에 시선을 모은다. 대화 내용은 12~13px, 첫 질문은 화면에 맞춰 24~32px로 표시한다. 화면별 가독성과 입력창 위치를 실제 브라우저에서 확인한다.

라이브러리와 도면은 같은 파라메트릭 3D 형상을 사용한다. WebGL을 사용할 수 없으면 아이콘과 2D로 대체한다. 과장된 AI 효과나 장식용 생성 이미지를 추가하지 않는다.

## 생성형 UI 기준

Google Cloud의 컴포넌트 선택형 GenUI, A2UI의 선언적 데이터·검증·상태 바인딩, Vercel AI SDK의 도구 결과를 인터랙티브 컴포넌트로 연결하는 원리를 참고한다. 프로젝트는 서버 없는 자체 JSON 스키마를 쓰며 A2UI 프로토콜 구현을 주장하지 않는다.

Gemma는 허용된 `ui` 값 하나를 선택한다. 앱이 이를 검증하고 자체 UI 컴포넌트와 실제 상태에 연결한다. 원시 HTML·CSS·JavaScript는 모델 응답에서 실행하지 않는다. 숫자·단위·경계·충돌은 앱이 계산한다. 직접 입력값과 요청하지 않은 속성을 보존한다.
