# 룸꾸 디자인 방향 · v5

v4까지는 왼쪽 상담·오른쪽 도면의 2단 화면에 탭(상담·공간 도구·가구 찾기·목록)을 얹은 구조였다. v5는 이 구조를 버리고 방 모형을 화면 전체에 깔았다. 대화는 그 위에 붙은 시트로 다시 설계했다. 색·글꼴·로고·아이콘·컴포넌트도 새로 만들었다.

## 방향 다섯 줄 (unslop)

- **제품:** 말이나 사진으로 방과 가구를 설명하면 편집 가능한 치수 초안이 생기고, 실제 크기의 2D·3D 방에 놓아보는 브라우저 인테리어 상담.
- **성격:** 차분하다, 재는 듯 정확하다, 손으로 만지는 맛이 있다.
- **세계:** 책상 위 종이에 놓인 1:50 실내 모형과 줄자. 벽은 단면처럼 윗면이 먹색이고, 바닥은 나무결이 보인다.
- **강조할 순간:** ① 화면 전체의 방 모형. ② 대화 안의 도구가 방을 바꾸는 순간, 특히 아직 놓지 않은 가구가 점선 유령으로 방 안에 먼저 나타나는 장면.
- **고유한 디테일:** 줄자 칩. 사용자가 직접 정한 치수는 눈금이 있는 노란 줄자로, 초안 치수는 점선 연필 테두리로 표시한다. 대화·도구·3D·2D가 같은 표시를 쓴다.

## 사용 흐름

| 상황 | 화면에서 일어나는 일 |
| --- | --- |
| 첫 진입 | 대화 시트에 “어떤 방을 꾸밀까요?”와 시작점 네 개(방 크기·가구 고르기·사진·벽과 바닥), 예시 문장이 보인다. 지금 방이 예시라는 사실과 “빈 방으로 시작”을 함께 알린다 |
| 방을 말함 | 상담 모델이 해석하고 앱이 숫자를 문장에서 읽어 바로 반영한 뒤 방 크기 도구를 띄운다(모델이 없으면 규칙). 방을 줄여 가구가 벽을 넘으면 배치 확인 도구가 함께 뜬다 |
| 가구를 말함 | 점선 초안이 방의 빈자리에 먼저 나타나고, 규격 비교 도구가 각 규격이 들어가는지 보여준다. 규격에 마우스를 올리면 방 안의 점선도 그 크기로 바뀐다 |
| 놓기 | 초안을 다루던 도구가 놓인 가구를 계속 다룬다. 대화는 그대로 남고, 입력창 대상이 그 가구로 바뀐다 |
| 가구 선택 | 도면 위 도구 막대(크기·색·회전·복제·삭제)가 가구 옆에 붙는다. 입력창에는 “선택한 가구” 칩이 생겨 “가로 140cm로”가 그 가구에 적용된다 |
| 공간 전환 | 대화는 한 줄기로 이어지고 전환 기록이 구분선으로 남는다. 다른 공간의 도구는 접힌 채 “다른 공간”으로 표시된다 |

메뉴를 찾아다니지 않도록 탭을 없앴다. 모든 도구는 대화 안에 나타나거나 입력창의 `+`에서 연다. 직접 연 도구도 대화 기록에 남는다.

## 입력창·대화·도구·미리보기의 관계

- **입력창**은 항상 보인다. 위에 대상 칩(방 / 선택한 가구 / 초안)이 있어 지금 말이 어디에 적용되는지 보여준다.
- **대화**는 턴마다 답, 생성된 도구, 바뀐 내용(변경 영수증), 다음에 할 일 칩을 가진다. 마지막 영수증에서 바로 되돌릴 수 있다.
- **도구**는 최신 턴의 것만 펼치고 이전 것은 한 줄 요약으로 접는다. 펼친 도구는 모두 실제 상태에 연결되어 있어 언제 다시 열어도 지금 값을 보여준다.
- **미리보기**는 화면 전체의 방이다. 대화 시트 폭만큼 카메라 중심을 옮겨 방이 남은 영역 가운데에 오게 했다.

## 데스크톱과 모바일

- **데스크톱:** 방이 화면 전체, 대화 시트가 왼쪽에 떠 있다(388~500px). 시트를 접으면 마지막 답과 입력창만 남는다.
- **모바일:** 방이 위, 대화가 아래 시트다. 시트는 손잡이를 누르거나 끌어 낮게·절반·전체로 바꾼다. 키보드가 올라오면 보이는 영역 높이(visualViewport)에 맞춰 입력창이 키보드 위에 남는다. 확대 버튼과 다시 실행처럼 덜 쓰는 도구는 숨긴다.

## 시각 기준

- **색:** 종이(#efede7)·시트(#fbfaf7)·먹(#1f1d19) 중립색. 강조색은 먹 하나로 주 버튼·선택에만 쓴다. 줄자 노랑(#f2c94c)은 직접 정한 치수와 선택한 가구 표시에만 쓴다. 경고는 #b03d29 한 가지다.
- **글꼴:** 본문은 Pretendard, 치수와 숫자는 JetBrains Mono. 굵기는 400·500·600만 쓴다.
- **아이콘:** Lucide, 18px, 획 1.5. 색은 글자 색을 따른다.
- **간격·모서리:** 4px 격자. 컨트롤 10px, 카드 14px, 시트 20px 모서리.
- **움직임:** 한 가지 곡선(cubic-bezier(0.22, 1, 0.36, 1)). 새 턴은 8px 떠오르며 나타난다. 반복 애니메이션은 실제로 진행 중인 모델 작업의 회전 표시뿐이다.
- **로고:** 방 모서리 두 벽과 노란 가구 한 개로 그린 평면 기호와 “룸꾸” 글자.

## 3D와 2D

- **3D:** 뒤·왼쪽 벽은 단면, 앞·오른쪽은 낮은 턱. 바닥은 나무결 판재 텍스처, 실내 환경광과 부드러운 그림자, 가구마다 얇은 외곽선을 둔다. 방과 선택한 가구의 치수는 줄자 라벨로 표시한다.
- **2D:** 건축 평면도처럼 벽은 먹색 단면이고 가구는 위에서 본 기호와 이름으로 그린다. 이름은 가구를 돌려도 똑바로 읽힌다.
- **키 비교:** 선택 입력으로 키에 맞춘 세이지색 모형을 가구와 같은 축척에 둔다. 서기·앉기·눕기는 대화 속 도구에서 바꾼다. 직접 입력한 키에는 노란 줄자 칩, 기본 170cm에는 점선 출처를 둔다. 신체 비율·착석 높이가 단순 모형이라는 설명을 도구에 표시한다.
- **집 전체:** 종이 위 2D 도면에 공간의 중심 좌표를 배치한다. 화장실은 옅은 회녹색 타일과 설비 기호로 구별한다. 공간은 끌어 옮기고 맞닿은 벽에 연결 문 초안을 그린다. 숫자 위치 입력과 방 편집 버튼도 대화 속 도구로 제공한다. 별도 탭을 만들지 않는다.
- WebGL을 쓸 수 없으면 2D로 열고, 사진 썸네일 대신 아이콘을 쓴다.

## 생성형 UI의 위치

Google Cloud 문서는 생성형 UI를 세 가지로 나눈다. 미리 만든 구성요소 중에서 고르는 정적 방식, 구조화된 스키마(JSON)를 돌려주는 선언적 방식, 원시 HTML·CSS를 생성하는 개방형 방식이다. 룸꾸는 정적 방식에 가깝다.

- 앱이 렌더링할 수 있는 컴포넌트는 `src/ui-schema.js`의 `SURFACE_KINDS` 16가지다. 상담 모델은 다음 도구(`MODEL_UI`: 방 크기·유형·마감, 가구 규격·치수·색상)와 동작(`MODEL_ACTIONS`: 가구 고르기·공간 목록·놓인 가구·저장·사용법·AI 설정 열기, 놓기·되돌리기 등)을 고른다. 배치 확인 도구는 앱이 겹침이 늘어날 때 붙인다. 키 비교와 집 전체 평면도는 사용자가 직접 여는 앱 도구다.
- 모델 응답은 허용 목록 값만 쓸 수 있는 JSON 스키마로 제한한다(WebLLM의 JSON 스키마 제약). 앱이 다시 검증하고 자체 컴포넌트에 실제 상태를 연결한다. 모델이 만든 마크업은 실행하지 않는다.
- 문서가 꼽은 운영 고려사항 네 가지에 맞춰 이렇게 처리했다. 신뢰 경계는 사전에 만든 컴포넌트만 렌더링하고 모델 결과를 검증해 바로잡은 내용을 보여주는 것으로 지킨다. 테스트는 픽셀 대신 컴포넌트가 나타나 동작하는지와 검증 규칙(단위 테스트)을 확인한다. 지연은 모델이 해석하는 동안 그 턴에 “해석하는 중”과 멈추기 버튼을 보이고, 25초가 넘으면 규칙으로 처리한다. 접근성은 각 컴포넌트에 ARIA 라벨과 역할을 넣었다.
- A2UI 프로토콜을 구현하거나 호환을 주장하지 않는다. 카탈로그가 렌더러와 에이전트 사이의 계약이고 원시 HTML·CSS·스크립트를 보내지 않는다는 A2UI의 원칙, 도구 결과를 컴포넌트로 연결하는 Vercel AI SDK의 방식을 참고했다.
