# 룸꾸 디자인 방향 · v5.8

v4까지는 왼쪽 상담·오른쪽 도면의 2단 화면에 탭(상담·공간 도구·가구 찾기·목록)을 얹은 구조였다. v5는 탭을 없애고 방 모형을 화면 전체에 깔았으며, 대화는 그 위에 떠 있는 488px 카드였다. v5.5에서 이 카드를 버렸다. 처음 보는 사람에게는 대화가 설정 패널처럼 보였고, 모델 상태는 입력창 아래 구석에 있었고, 집 전체에서 방을 붙이려면 공간 목록 맨 아래를 찾아야 했기 때문이다. 지금은 왼쪽이 화면 높이를 다 쓰는 **상담 대화**, 오른쪽이 방이다. 색·글꼴·줄자 칩 같은 v5의 재료는 그대로 쓴다.

v5.6에서는 v5.5를 써 본 뒤 나온 네 가지를 고쳤다. 대화 열의 기본 폭을 화면의 절반으로 넓히고 경계에 늘 보이는 손잡이를 달았다. 모델 아일랜드를 방 쪽 가운데가 아니라 화면 가운데에 둔다. 아바타는 방 안이 아니라 방 바깥 벽 끝 옆에서 시작한다. 휴대 기기에서는 상담 모델을 받기 전에 먼저 묻는다. 2026-11-16 추가 요청으로 기본 모델을 컴퓨터용 Gemma 4 E2B(약 2.8GB)로 바꿨다.

구조를 다시 짤 때 참고한 공개 사례:

- **대화 열:** Bolt는 대화 열 폭을 CSS 변수로 두고(최대 37rem) 나머지를 작업 화면에 준다. Lovable은 전체 높이의 왼쪽 대화 열 아래에 입력창을 두고, 답 뒤에 제안 칩을 붙이며, 에이전트가 한 일을 대화 속 카드로 보여 준다. ([Bolt 변수](https://raw.githubusercontent.com/stackblitz/bolt.new/main/app/styles/variables.scss), [Lovable 문서](https://docs.lovable.dev/features/projects/chat.md))
- **공간 붙이기:** FigJam은 고른 도형의 가장자리에 빠른 만들기 손잡이를 띄우고 그 방향으로 다음 도형을 미리 보여 준다. Live Home 3D는 방을 그리다 벽이 겹치면 하나의 벽으로 합친다. magicplan은 방 종류를 먼저 고르고 치수를 바꾼다. ([FigJam](https://help.figma.com/hc/en-us/articles/1500004291601), [Live Home 3D](https://www.livehome3d.com/support/lh3d-help/working-with-objects-walls), [magicplan](https://help.magicplan.app/create-a-room-with-the-square-room-feature))
- **받기 전에 묻기:** Chrome의 내장 AI 안내서는 모델을 내려받아야 하는 기능에서 걸리는 시간을 사용자에게 미리 알리고(“It's best practice to alert the user to the time required to perform these downloads.”), 단추를 누른 뒤에 받기 시작해 진행률을 보여 주며, 다 받은 뒤 준비하는 동안에는 끝을 알 수 없는 표시로 바꾸라고 권한다. 룸꾸는 여기에 크기와 보관 위치를 더해 묻는다. ([Chrome for Developers](https://developer.chrome.com/docs/ai/inform-users-of-model-download))
- **준비 알림:** Apple의 Live Activity는 접힌 모양에 꼭 필요한 값만 두고 누르면 펼치며, 일이 끝나면 바로 거둔다. Sonner의 진행 알림은 받는 동안 스스로 닫히지 않고 제자리에서 성공·실패로 바뀐다. ([Apple HIG](https://developer.apple.com/design/human-interface-guidelines/live-activities), [Sonner](https://sonner.emilkowal.ski/toast))

## v5.8 상담 초안과 모델 선택

집 전체 요청은 대화 속 구성표로 답한다. 테마의 벽·바닥·가구 색과 공간별 면적·가구를 보여 주고, 적용 전까지 실제 배치를 유지한다. 적용하면 실행 취소 한 번으로 되돌린다. 직접 편집한 뒤에는 오래된 초안을 비활성화하고 이유를 적는다.

모델 선택은 대화 머리의 CPU 버튼에서 바로 연다. 네 후보의 다운로드 크기와 GPU 메모리를 함께 적고, 선택 상태는 테두리와 라디오 의미로 구별한다. 키보드 방향키는 모델 선택에만 작동한다. 모바일 첫 다운로드 팝업에도 선택란을 두며, 바꾼 모델의 실제 크기를 확인하고 동의해야 받는다.

## 방향 다섯 줄 (unslop)

- **제품:** 말이나 사진으로 방과 가구를 설명하면 편집 가능한 치수 초안이 생기고, 실제 크기의 2D·3D 방에 놓아보는 브라우저 인테리어 상담.
- **성격:** 차분하다, 재는 듯 정확하다, 손으로 만지는 맛이 있다.
- **세계:** 책상 위 종이에 놓인 1:50 실내 모형과 줄자. 벽은 단면처럼 윗면이 먹색이고, 바닥은 나무결이 보인다.
- **강조할 순간:** ① 룸꾸와 말을 주고받으면 옆의 방이 바뀌는 순간. ② 대화 안의 도구가 방을 바꾸는 순간, 특히 아직 놓지 않은 가구나 붙이려는 공간이 점선으로 먼저 나타나는 장면.
- **고유한 디테일:** 줄자 칩. 사용자가 직접 정한 치수는 눈금이 있는 노란 줄자로, 초안 치수는 점선 연필 테두리로 표시한다. 대화·도구·3D·2D가 같은 표시를 쓴다.

## 사용 흐름

| 상황 | 화면에서 일어나는 일 |
| --- | --- |
| 첫 진입 | 대화는 룸꾸의 인사 말풍선으로 시작한다. 그 아래에 “무엇부터 할까요?”와 시작점 여섯 개(방 크기·가구 고르기·사진·벽과 바닥·내 키·집 전체), 예시 문장이 답 고르기처럼 붙는다. 지금 방이 예시라는 사실과 “빈 방으로 시작”을 두 번째 말풍선으로 알린다. 대화가 시작되면 인사 한 줄만 맨 위에 남는다 |
| 방을 말함 | 상담 모델이 해석하고 앱이 숫자를 문장에서 읽어 바로 반영한 뒤 방 크기 도구를 띄운다(모델이 없으면 규칙). 방을 줄여 가구가 벽을 넘으면 배치 확인 도구가 함께 뜬다 |
| 가구를 말함 | 점선 초안이 방의 빈자리에 먼저 나타나고, 규격 비교 도구가 각 규격이 들어가는지 보여준다. 규격에 마우스를 올리면 방 안의 점선도 그 크기로 바뀐다 |
| 놓기 | 초안을 다루던 도구가 놓인 가구를 계속 다룬다. 대화는 그대로 남고, 입력창 대상이 그 가구로 바뀐다 |
| 가구 선택 | 도면 위 도구 막대(크기·색·회전·복제·삭제)가 가구 옆에 붙는다. 입력창에는 “선택한 가구” 칩이 생겨 “가로 140cm로”가 그 가구에 적용된다 |
| 공간 전환 | 대화는 한 줄기로 이어지고 전환 기록이 구분선으로 남는다. 다른 공간의 도구는 접힌 채 “다른 공간”으로 표시된다 |
| 키로 가늠 | 방 아래 사람 버튼을 누르거나 키를 말하면 같은 축척의 아바타가 방 바깥 벽 끝 옆에 선다. 방 안 가구를 가리지 않고, 벽 높이와 바로 견줄 수 있는 자리다. 끌어서 방 안으로 들이거나 다시 밖에 세운다. 머리 위 이름표를 누르면 서기·앉기·눕기 막대로 펼쳐진다. 의자·소파·침대를 고르면 가구 도구 막대에 앉히기·눕히기가 생긴다 |
| 집 전체 | 위쪽 길잡이에서 집 전체로 나간다. 공간마다 이름표가 붙고, 고른 공간의 이름표에 `방 편집`이 붙는다. 2D에서는 공간을 끌어 집 모양을 맞추고 3D에서는 돌려 본다 |
| 공간 붙이기 | 고른 공간의 벽 바깥에 점선 `+` 손잡이가 뜬다. 누르면 그 벽에 붙일 공간 종류와 기본 크기가 나오고, 가리키면 붙을 자리가 점선으로 도면에 먼저 보인다. 고르면 벽에 맞닿아 놓이고 문이 이어지며 새 공간이 고른 공간이 된다. 위쪽 `공간 추가`도 같은 창을 연다. 좁은 화면에서는 고르는 창이 방 아래 도구 줄 위에 옆으로 넘기는 줄로 깔린다 |
| 문 | 2D에서 문을 끌면 벽을 따라 5cm 단위로 움직인다. 누르면 문 위에 막대가 떠서 폭(5cm씩)·여는 방향·막기를 바꾼다. 집 전체 도구의 문 목록에서는 벽 끝에서의 거리와 폭을 숫자로 넣고, 막은 벽에 문을 다시 낸다 |
| 모델 받기 묻기 | 휴대 기기에서 모델이 보관돼 있지 않으면, 아일랜드 자리에 같은 먹색 팝업이 뜨고 뒤 화면을 옅게 가린다. 이름·크기·보관 위치와 `모델 받기`·`나중에`를 보여 준다. 누르기 전에는 아무것도 받지 않는다. 받겠다고 누르면 팝업이 그 자리에서 진행 안내로 바뀐다. `나중에`를 고르면 규칙으로 상담하고 대화 위쪽에 `모델 받기`가 남는다. 받다 만 모델이면 남은 양만 적고 `이어서 받기`라고 묻는다. 컴퓨터에서는 묻지 않는다 |
| 모델 준비 | 화면 위 가운데(대화 머리와 방 위 도구 줄 바로 아래)에 먹색 캡슐이 떠서 받는 중·준비 중·완료·실패를 한 줄로 알린다. 누르면 아래로 펼쳐져 이름·크기·받은 양·취소가 보인다. 컴퓨터에서 처음 받을 때는 펼쳐진 채 나타났다가 7초 뒤 접힌다 |

메뉴를 찾아다니지 않도록 탭을 없앴다. 값을 정하는 도구는 대화 안에 나타나거나 입력창의 `+`에서 연다. 직접 연 도구도 대화 기록에 남는다.

v5.3까지는 키 비교와 집 전체가 `+` 메뉴의 일곱·여덟 번째 항목과 공간 목록 안에만 있어서 처음 쓰는 사람이 찾기 어려웠다. v5.4에서 “무엇을 어떻게 보는가”를 방 위로 올렸다. 범위(집 전체 ↔ 지금 방)와 보기(2D/3D), 표시(아바타·격자·치수)는 방 위의 컨트롤이 맡고, 고른 대상(가구·아바타·공간)에는 그 자리에 도구가 붙는다.

## 입력창·대화·도구·미리보기의 관계

- **입력창**은 항상 보인다. 위에 대상 칩(방 / 선택한 가구 / 초안)이 있어 지금 말이 어디에 적용되는지 보여준다.
- **대화**는 턴마다 답, 생성된 도구, 바뀐 내용(변경 영수증), 다음에 할 일 칩을 가진다. 마지막 영수증에서 바로 되돌릴 수 있다.
- **도구**는 최신 턴의 것만 펼치고 이전 것은 한 줄 요약으로 접는다. 펼친 도구는 모두 실제 상태에 연결되어 있어 언제 다시 열어도 지금 값을 보여준다.
- **미리보기**는 대화 오른쪽의 방이다. 대화 폭을 바꾸면 방이 남은 영역 가운데로 다시 맞춰진다.
- **누가 답하는지**는 대화 머리의 이름 아래 한 줄에 둔다(“Gemma 4 E2B가 이 기기에서 답해요”, “모델 꺼 둠 · 규칙으로 답해요 켜기”). 답마다 그 턴을 무엇이 처리했는지는 답 아래 작은 글로 남긴다.

## 데스크톱과 모바일

- **데스크톱(900px 이상):** 왼쪽이 화면 높이를 다 쓰는 대화 열이다. 기본 폭은 화면의 절반이다. 경계 가운데에 늘 보이는 손잡이를 끌거나 방향키로 360px부터 화면의 70%까지 바꾸고, 두 번 누르면 절반으로 돌아간다. 방 쪽에는 위 도구 줄이 들어갈 520px을 늘 남긴다. 대화 글은 열이 넓어져도 680px을 넘지 않는다. 열을 접으면 마지막 답과 입력창만 남은 카드가 왼쪽 아래에 뜬다. 방 쪽이 좁아지면 위 도구 줄이 크기 표시, `공간 추가` 글자, 다른 범위의 이름 순서로 접힌다. 방 위쪽에는 길잡이(집 전체 | 지금 방)·실행 취소·2D/3D·`⋯`, 아래쪽에는 조작 안내와 사람·격자·5cm·치수·화면 맞춤 버튼이 있다.
- **모바일(900px 미만):** 방이 위, 대화가 아래 시트다. 왼쪽 여백을 아끼려고 룸꾸의 얼굴과 이름을 말풍선 위 한 줄로 올린다. 시트는 손잡이를 누르거나 끌어 낮게·절반(54%)·전체로 바꾼다. 키보드가 올라오면 보이는 영역 높이(visualViewport)에 맞춰 입력창이 키보드 위에 남는다. 길잡이는 지금 범위의 이름만 적고 다른 쪽은 아이콘으로 줄인다. 실행 취소는 방 아래 왼쪽으로 내리고, 격자·5cm 설정은 `⋯`로 옮겼다. 방 모형은 아래 버튼 줄만큼 띄워 그려서 버튼에 가리지 않는다. 낮춘 시트는 마지막 답 한 줄과 입력창만 남긴다.
- **길잡이:** 지금 범위의 버튼이 먹색으로 채워진다. 다른 쪽을 누르면 범위가 바뀌고, 지금 범위를 다시 누르면 공간 목록이 열려 방을 옮기거나 지금 방 옆에 새 공간을 붙인다.
- **입력창의 `+`:** 가구 → 공간 → 가늠·집 전체 → 파일·설정 순서로 묶어 두 줄로 놓았다. 입력창 위의 여유만큼만 열려 낮은 시트에서도 잘리지 않는다.

## 시각 기준

- **색:** 종이(#efede7)·시트(#fbfaf7)·먹(#1f1d19) 중립색. 강조색은 먹 하나로 주 버튼·선택에만 쓴다. 줄자 노랑(#f2c94c)은 직접 정한 치수와 선택한 가구 표시에만 쓴다. 경고는 #b03d29 한 가지다.
- **글꼴:** 본문은 Pretendard, 치수와 숫자는 JetBrains Mono. 굵기는 400·500·600만 쓴다.
- **아이콘:** Lucide, 18px, 획 1.5. 색은 글자 색을 따른다.
- **간격·모서리:** 4px 격자. 컨트롤 10px, 카드 14px, 시트 20px 모서리.
- **말풍선:** 룸꾸의 말은 흰 종이 말풍선(왼쪽, 얼굴 표식), 사용자의 말은 먹색 말풍선(오른쪽)이다. 버튼을 눌러 한 일은 테두리만 있는 알약으로 구별한다. 도구 카드와 변경 영수증은 룸꾸의 말풍선 아래 같은 열에 붙는다.
- **움직임:** 한 가지 곡선(cubic-bezier(0.22, 1, 0.36, 1)). 새 턴은 8px 떠오르며 나타난다. 반복 애니메이션은 실제로 진행 중인 일에만 쓴다: 답을 쓰는 중의 점 세 개, 모델을 준비하는 중의 회전 표시(60초 넘게 멈춰 있으면 회전도 멈추고 글로 알린다). 대화 머리의 상태 줄은 돌지 않는 점으로만 표시한다.
- **로고:** 방 모서리 두 벽과 노란 가구 한 개로 그린 평면 기호와 “룸꾸” 글자.

## 3D와 2D

- **3D:** 뒤·왼쪽 벽은 단면, 앞·오른쪽은 낮은 턱. 바닥은 나무결 판재 텍스처, 실내 환경광과 부드러운 그림자, 가구마다 얇은 외곽선을 둔다. 방과 선택한 가구의 치수는 줄자 라벨로 표시한다.
- **2D:** 건축 평면도처럼 벽은 먹색 단면이고 가구는 위에서 본 기호와 이름으로 그린다. 이름은 가구를 돌려도 똑바로 읽힌다.
- **키 비교:** 건축 모형에 세우는 축척 인형처럼 단순한 세이지색 관절 모형을 가구와 같은 축척에 둔다. 머리 꼭대기가 정확히 키 높이다. 새로 세우면 방 바깥 앞쪽 왼 모서리 옆에 선다. 기본 3D 시점에서 몸이 방 안을 가리지 않고, 벽 끝과 나란히 서서 벽 높이와 키를 바로 견줄 수 있는 자리다. 방 밖에서는 방바닥과 같은 높이의 종이색 받침 위에 서고(2D에서는 원), 도면과 3D는 그 자리까지 담도록 다시 맞춘다. 끄는 동안에는 축척을 그대로 두었다가 놓은 뒤에 맞춘다. 벽 위에 놓으면 벽에 걸치지 않고 가까운 쪽으로 붙는다. 그 자리에 다른 공간이 붙어 있거나 높은 벽 뒤에 숨게 되면 다음 자리(뒤쪽 오른 모서리 옆, 앞쪽 벽 앞, 오른쪽 벽 옆)를 고른다. 2D에서 방 앞쪽 바깥에 서 있으면 이름표를 몸 아래에 둔다. 앉으면 좌판 위에서 등받이에 등을 대고, 좌석이 허벅지보다 깊으면 무릎이 좌석 끝에 오도록 나와 기대앉는다. 낮은 좌석에서는 무릎을 세우고 높은 좌석에서는 발이 뜬다. 누우면 머리를 헤드보드 쪽 베개에 두고 이불 위에 놓인다. 머리 위 이름표는 줄자 칩이다: 직접 정한 키는 노란 줄자, 기본 170cm는 점선. 대화 속 도구는 키와 가구 높이를 같은 축척의 정면도로 나란히 세운다. 안내 문구는 “모형 기준”임을 밝힌다.
- **집 전체:** 2D와 3D가 공간의 중심 좌표를 공유한다. 2D에서 공간을 끌어 옮기고, 3D에서 집을 돌려보거나 공간을 선택해 방 편집으로 들어간다. 고른 공간은 바닥 가장자리의 줄자 노랑 띠와 먹색 이름표로 표시한다. 화장실은 옅은 회녹색 타일과 변기·세면대·샤워 공간의 초안 모형으로 구별하고, 설비는 문 맞은편 벽에 붙인다. 내부 벽은 85cm 단면으로 낮추고 연결 문 구간을 비워 가구와 설비를 볼 수 있게 한다. 문은 넓은 공간 쪽으로 열리는 점선 호로 그린다. 방 편집 화면에도 같은 문 자리가 비어 있어 문 앞에 가구를 놓지 않게 돕는다. 렌더러를 추가하지 않는다.
- **이름표:** 방 이름·키·문은 캔버스 글자가 아니라 화면 위의 이름표다. 공간이 많거나 방이 아주 좁으면 크기, 이름 순서로 접어 아이콘만 남기고, 고른 공간은 줄이지 않는다. 방 이름표는 2D에서 공간 안쪽 왼쪽 위에, 3D에서는 화면 아래쪽 바닥 변에서 조금 안으로 들어온 자리에 놓여 자기 공간의 바닥 위에 있다. 겹치는 이름표는 아래로 밀어낸다. 좁은 공간에서는 크기 표시를 먼저 접고 이름을 남긴다. 방 편집 화면의 문 이름표(점선)는 문 너머 공간의 이름을 적고, 누르면 그 공간으로 간다. 아바타가 올라간 가구를 고르면 가구 도구 막대가 그 자리를 쓰므로 키 이름표를 숨긴다. 이미지로 저장할 때 같은 자리에 그린다.
- **공간 붙이기:** `+` 손잡이는 아직 없는 공간이라는 뜻으로 점선 원이다. 누르면 먹색으로 채워진다. 이름표와 겹치면 손잡이가 벽을 따라 비키고, 문 위에는 놓이지 않는다. 미리 보기는 점선 테두리에 크기를 적는다. 고르는 동안에는 가장 큰 후보가 들어갈 만큼 도면을 미리 줄여, 종류를 바꿔 봐도 축척이 흔들리지 않는다.
- **문:** 자동으로 놓인 문은 점선 호, 직접 옮기거나 폭을 정한 문은 실선 호다. 고른 문은 문턱에 줄자 노랑 선을 긋는다. 문 막대의 폭 칩은 가정값 80cm일 때 점선, 직접 정하면 노란 줄자다. 문 막대가 떠 있는 동안 그 밑에 깔리는 이름표는 잠시 숨겨 문을 바로 끌 수 있게 한다.
- **모델 아일랜드:** 화면 위 가운데의 먹색 캡슐이다. 대화 폭을 바꿔도 화면 가운데에 있다. 대화 머리나 방 위 도구 줄과 같은 줄에 두면 단추를 가리므로 그 줄 바로 아래에 둔다. 먹색 말풍선 위에 떠도 한 덩어리로 보이지 않게 종이색 테를 두른다. 모바일에서 대화를 화면 가득 펼치면 대화 머리 아래로 내려간다. 접힌 모양은 고리(받은 비율)·한 줄 글·퍼센트이고, 펼치면 눈금이 있는 줄자 막대와 받은 양, 받는 동안에도 규칙으로 답한다는 안내, 취소가 보인다. 화면을 막지 않고 초점을 가져가지 않는다. 잠깐 뜨는 알림도 같은 가운데 축에 뜨고, 아일랜드가 있으면 그 아래로 내려간다.
- **받기 전에 묻는 팝업:** 아일랜드와 같은 자리·재질이고 폭은 380px까지다. 화면을 가리는 유일한 창이다. 초점은 단추가 아니라 팝업 자체에 둬서 Enter 한 번에 큰 파일을 받기 시작하지 않게 한다. 크기는 줄자 노랑으로 적는다. 단추는 44px 높이다. Esc나 바깥을 누르면 `나중에`와 같다.
- WebGL을 쓸 수 없으면 2D로 열고, 사진 썸네일 대신 아이콘을 쓴다.

## 생성형 UI의 위치

Google Cloud 문서는 생성형 UI를 세 가지로 나눈다. 미리 만든 구성요소 중에서 고르는 정적 방식, 구조화된 스키마(JSON)를 돌려주는 선언적 방식, 원시 HTML·CSS를 생성하는 개방형 방식이다. 룸꾸는 정적 방식에 가깝다.

- 앱이 렌더링할 수 있는 컴포넌트는 `src/ui-schema.js`의 `SURFACE_KINDS` 18가지다. 상담 모델은 다음 도구(`MODEL_UI`: 방 크기·유형·마감, 가구 규격·치수·색상)와 동작(`MODEL_ACTIONS`: 가구 고르기·공간 목록·놓인 가구·저장·사용법·AI 설정 열기, 놓기·되돌리기 등)을 고른다. 배치 확인 도구는 앱이 겹침이 늘어날 때 붙인다. 키 비교와 집 전체는 사용자가 직접 여는 앱 도구다.
- 모델 응답은 허용 목록 값만 쓸 수 있는 JSON 스키마로 제한한다(WebLLM의 JSON 스키마 제약). 앱이 다시 검증하고 자체 컴포넌트에 실제 상태를 연결한다. 모델이 만든 마크업은 실행하지 않는다.
- 문서가 꼽은 운영 고려사항 네 가지에 맞춰 이렇게 처리했다. 신뢰 경계는 사전에 만든 컴포넌트만 렌더링하고 모델 결과를 검증해 바로잡은 내용을 보여주는 것으로 지킨다. 테스트는 픽셀 대신 컴포넌트가 나타나 동작하는지와 검증 규칙(단위 테스트)을 확인한다. 지연은 모델이 해석하는 동안 그 턴에 “해석하는 중”과 멈추기 버튼을 보이고, 25초가 넘으면 규칙으로 처리한다. 접근성은 각 컴포넌트에 ARIA 라벨과 역할을 넣었다.
- v5.9부터 A2UI 1.0 공식 코어와 룸꾸 커스텀 카탈로그를 쓴다. 검증한 도구 명세를 앱에서 메시지로 바꾸고 SDK가 해석한 컴포넌트·바인딩만 기존 Preact 카드로 렌더링한다. 카드 내부와 2D·3D 편집은 기존 앱 연산이 맡는다. 프로토콜 오류는 해당 카드에서 복구하고 입력창·배치는 보존한다. 범위는 [A2UI 연결](a2ui.md)에 기록한다.

## v5.10 창문과 확장 카탈로그

기존 종이·먹색·줄자 노랑과 상담/방 구성을 유지한다. 창문 도구는 입력창의 +와 벽·바닥 도구에서 연다. 창문마다 네 방향과 폭·높이·벽 끝 거리·바닥 높이를 정한다. 직접 정한 값은 노란 줄자 표시로 구별하고, 폼은 두 열·최소 44px 컨트롤을 쓴다. 잘못된 입력은 해당 창 아래에 이유와 고칠 방법을 남기며 입력값을 보존한다. 창이 없을 때는 추가할 벽과 첫 창문 추가를 보여 준다.

3D는 창의 사각 구간을 벽에서 비우고 옅은 청회색 유리와 프레임을 둔다. 앞·오른쪽의 낮춘 벽에서도 프레임은 설정한 높이에 남는다. 2D는 같은 벽 구간에 세 줄 창 기호를 그린다. 햇빛 효과를 넣거나 채광을 계산한 것처럼 표시하지 않는다. 가구 목록은 40종·123개 크기 초안이며 검색 결과 수와 초기화 경로를 둔다.
