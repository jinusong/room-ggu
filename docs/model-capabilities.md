## v5.11 모델별 지원 범위 (2026-11-17)

네 상담 모델은 룸꾸의 같은 편집 도구를 사용한다. 가구 40종, 방 유형과 치수, 벽과 바닥, 여러 가구 요청, 집 전체 초안을 다룬다. 모델이 공간별 가구 구성을 고르면 앱이 크기, 경계, 충돌을 검사한다. 집 전체는 40~660m², 최대 12개 공간과 8개 테마의 배치 초안이다.

창문 위치와 크기는 화면에서 직접 조절한다. 사진 판별은 별도 SigLIP 모델이 기존 20종만 다룬다. 사진만으로 실제 cm 치수를 재거나 채광, 일조량, 시공 도면을 계산하지 않는다.

| 모델 | 가구, 방, 복수 요청 | 분위기 | 집 전체 | 응답 중앙값 | 앱 보정이 있던 요청 |
| --- | --- | --- | --- | --- | --- |
| Gemma 4 E2B | 4/4 | 0/1 | 1/1 | 7.0초 | 4/6 |
| Gemma 3 1B | 4/4 | 1/1 | 1/1 | 2.1초 | 4/6 |
| Qwen3 0.6B | 4/4 | 0/1 | 1/1 | 1.7초 | 3/6 |
| Qwen3 1.7B | 4/4 | 1/1 | 1/1 | 3.2초 | 4/6 |

이번 구현에서 같은 여섯 문장을 f16 지원 기기의 Chrome WebGPU로 실행했다. 앱 보정 뒤 상태를 검사했으며 규칙 대체를 모델 성공으로 세지 않았다. 응답 시간은 모델 준비 뒤 전송부터 앱의 처리 완료까지다. 모델 자체 정확도나 일반적인 우열을 나타내는 점수는 아니다. 기기와 요청이 바뀌면 결과도 달라진다.

분위기 문장은 “벽은 따뜻한 느낌으로 하고 바닥은 짙은 원목으로”다. 카탈로그의 샌드 벽과 월넛 바닥을 비교 기준으로 삼았다. Gemma 4는 세이지와 월넛을 골랐고 Qwen3 0.6B는 마감 도구만 열어 색을 바꾸지 않았다. 두 모델은 색 이름을 구체적으로 정해 요청하는 편이 낫다. 초기 평가는 벽 변경 유무만 확인했으나 색 해석까지 비교하도록 기준을 좁혀 저장된 원시 답과 대조했다.

Qwen3 0.6B는 자유 답문을 쓰지 않고 의도와 속성만 고른다. 앱이 실제 변경 결과로 답문을 작성한다. 나머지 세 모델도 허용된 구조 안에서 답하며 앱이 고친 부분이 있으면 실제 결과로 안내한다. Gemma 3 1B의 f16을 지원하지 않는 기기에서는 Qwen3 0.6B f32로 대체하므로 이 표의 Gemma 3 결과를 그대로 적용하지 않는다.

비교 중 모델이 새 가구를 초안 없이 놓으려던 동작을 고쳤다. 앱이 치수 축 “깊이”를 물건 이름으로 읽던 오류도 고쳤다. 표는 수정 뒤 실행 결과다. Qwen3 1.7B는 첫 준비가 4분을 넘어 한 번 중단됐으며 보관된 파일을 이어 사용한 재시도에서 실제 추론을 마쳤다.

실행: `node eval/chat/capability-qa.mjs`. 한 모델 재검사는 `MODEL=balanced node eval/chat/capability-qa.mjs`. 평가 프로필과 캐시 주소는 스크립트의 로컬 경로를 사용한다. 원본은 [평가 JSON](../eval/chat/results/capabilities-v5.11.json), UI 요약은 [model-benchmark.json](../src/app/model-benchmark.json)이다. `node scripts/summarize-model-capabilities.mjs`로 원시 답의 분위기 기준을 대조하고 요약을 만든다. 이전 버전의 50건 평가도 `eval/chat/results/full-qa-*.json`에 남아 있으나 이번 화면에는 현재 6문장 결과만 표시한다.
