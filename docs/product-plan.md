사용자는 공간 유형과 크기를 선택하거나 대화로 정한다. 가구 사진 또는 설명을 바탕으로 치수 초안을 조절하고 방에 배치한다. 여러 공간을 따로 저장해 전환할 수 있다.

## A 사용 흐름
```flow
공간 유형 선택 또는 상담 -> 방 편집: 유형·크기·벽·바닥
방 편집 -> 가구 라이브러리: 20종·63가지 치수 초안
가구 라이브러리 -> 가구 상담: 종류와 크기 단서
가구 상담 -> 치수 카드: 가로·깊이·전체 높이
치수 카드 -> 사용자 수정: 입력 근거 표시
사용자 수정 -> 2D 평면 배치: 이동·회전·겹침 확인
2D 평면 배치 -> 3D 공간: 같은 크기와 배치
3D 공간 -> 저장: 배치 JSON 또는 PNG
```

## B AI와 계산의 역할
| 역할 | 처리 |
|---|---|
| 사진 이해 | SmolVLM이 가구의 보이는 종류·형태를 설명 |
| 대화 이해 | Gemma가 공간 유형·크기 느낌 또는 가구 인원수·깊이·높이 단서를 정리 |
| 치수 초안 | 앱이 가구 유형과 단서를 편집 가능한 시작값으로 변환 |
| 값 보호 | 사용자가 정한 숫자를 우선하고 잘못된 제안은 거절 |
| 공간 계산 | 프론트 코드가 실제 단위·회전·경계·겹침을 계산 |

모델은 실측기를 대신하지 않는다. 사진 속 실제 cm 치수는 확정하지 않으며, 모델이 정리한 단서를 가구 유형별 시작값에 반영한다.

## C 기능과 데이터
- 원룸·거실·침실·서재·다이닝룸·주방·아이 방, 7가지 공간 유형
- 공간별 3가지 크기 초안과 가로·세로·천장 높이 실시간 편집
- 벽·바닥 색상 변경, 최대 12개 독립 공간 저장·전환
- 가구 20종·63개 치수 초안, 검색·분류·실제 형상 미리보기
- 가구 직접 입력·색상·치수 변경
- 대화 또는 사진으로 가구 등록
- 2D·3D 이동, 회전, 복제, 삭제
- 실행 취소·다시 실행, 벽까지 거리, 충돌 표시
- 브라우저 자동 저장, JSON 입출력, PNG 저장

“거실 가로 5m 세로 4m로 바꿔줘”, “아담한 서재 하나 추가해줘” 같은 대화가 공간 상태와 2D·3D에 반영된다. 명시한 숫자는 모델 응답을 기다리기 전에 반영한다. 면적만 알려주면 현재 비율로 가로·세로를 나누고 가정임을 표시한다.

각 공간은 독립된 직사각형 평면이다. 여러 방이 이어진 집 전체 도면은 만들지 않는다. 방 크기·위치는 미터, 가구 치수는 센티미터로 관리한다. 배치 파일의 치수 순서와 화면 순서는 명시적으로 변환한다.

## D 서버 없는 구성
```flow
브라우저 화면 -> 기본 상담: 규칙 기반
브라우저 화면 -> AI Worker: 요청과 진행 상태
AI Worker -> 공개 모델 파일: 최초 다운로드
AI Worker -> 치수 단서: 로컬 추론
치수 단서 -> 브라우저 화면: 검증 후 적용
브라우저 화면 -> 로컬 저장소: 배치 상태
```

모델·라이브러리를 내려받는 네트워크 요청은 발생한다. 사용자 사진과 대화의 추론은 기기 안에서 수행하며, 서버 저장 기능은 없다. 모델 파일은 브라우저 캐시에 보관될 수 있다.

## E 공용 개발 파이프라인
```flow
기획 설명 -> 화면 구현: answer-me-with-html
화면 구현 -> 디자인 점검: unslop
디자인 점검 -> 문구 점검: humanizer
문구 점검 -> 검증: 테스트와 브라우저
검증 -> GitHub Pages: 단계별 커밋·푸시
```

두 에이전트는 같은 스킬 원본과 제품 규칙을 읽는다. upstream 버전과 라이선스를 고정하고, 변경할 때 새 버전을 검토한다. 자동 스케줄러가 아니라 요청된 작업 안에서 실행하는 개발 절차다.
