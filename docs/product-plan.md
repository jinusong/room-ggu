방 모형이 화면 전체를 채우고 대화가 그 위에 시트로 붙는다. 사용자는 말이나 사진으로 방과 가구를 설명한다. 그 순간 필요한 도구가 대화 안에 나타나고 방이 바로 바뀐다. 탭과 별도 메뉴는 없다.

## A 사용 흐름
```flow
(말하기) -> 상담 모델: Gemma가 의도·가구·도구 해석
(사진) -> 사진 모델: SigLIP이 가구 종류 판별
상담 모델 -> 앱 검증: 숫자·이름·말하지 않은 속성
사진 모델 -> 앱 검증: 확률 70% 미만이면 후보만
앱 검증 -> 방 바로 반영: 크기·마감·점선 초안
방 바로 반영 -> 대화 안의 도구: 크기·규격·마감·색
대화 안의 도구 -> 방 바로 반영
(말하기) --> 규칙 상담: 모델 준비 중·꺼짐·미지원·실패
규칙 상담 --> 방 바로 반영
방 바로 반영 -> 놓기·선택: 대상 칩이 바뀜
```

기본은 모델이 해석한다. 사이트를 열면 상담 모델을 자동으로 준비하고, 준비되기 전이나 쓸 수 없는 기기에서는 규칙이 같은 계획 형식으로 대신 답한다. 답마다 무엇이 해석했는지와 규칙으로 처리한 이유를 적는다.

## B 화면 구성
| 영역 | 데스크톱 | 모바일 |
|---|---|---|
| 방 모형 | 화면 전체, 대화 시트만큼 카메라 중심을 옮김 | 위쪽, 시트 높이만큼 중심을 옮김 |
| 대화 시트 | 왼쪽에 떠 있음, 접으면 마지막 답과 입력창만 | 아래 시트, 낮게·절반·전체 3단 |
| 입력창 | 대상 칩 + 입력 + 도구(+) + 사진 + 보내기 | 같음, 키보드 위에 유지 |
| 방 위 도구 | 공간 전환·되돌리기·2D/3D·파일 메뉴, 격자·자석·치수·시점 | 덜 쓰는 도구는 숨김 |
| 선택한 가구 | 가구 옆에 붙는 도구 막대 | 같음, 아이콘만 |

## C 대화에 나타나는 도구
| 요청 예시 | 나타나는 도구 | 연결되는 상태 |
|---|---|---|
| 거실 가로 5m 세로 4m | 방 크기 | 가로·세로·천장, 크기 초안 3개, 평면 미리보기 |
| 책 읽는 아담한 방 | 방 크기 또는 공간 유형 | 7가지 유형, 직접 정한 치수는 유지 |
| 벽은 세이지, 바닥은 월넛 | 벽과 바닥 | 지금·바꾸기 전(또는 미리보기) 모서리 비교 |
| 두 명이 앉는 소파 | 규격 비교 | 규격마다 들어가는지·겹치는지·방보다 큰지 |
| 책상 가로 120cm | 치수 직접 입력 | 가로·깊이·높이, 줄자 칩으로 출처 표시 |
| 소파는 네이비로 | 가구 색상 | 10가지 색 + 직접 고르기 |
| 방을 줄여 가구가 벽을 넘음 | 배치 확인 | 겹침·넘침 목록, 빈자리로 옮기기 |
| 가구 고르기 / 공간 목록 / 저장 | 가구 고르기·내 공간·저장과 불러오기 | 20종 썸네일, 12개 공간, JSON·PNG |

최신 턴의 도구만 펼치고 이전 도구는 한 줄로 접는다. 접힌 도구도 다시 열면 지금 상태를 보여준다. 초안을 다루던 도구는 놓인 가구를 계속 다룬다.

## D 모델과 앱의 경계
```flow
사용자 문장 -> 브라우저 Worker: Gemma 3 1B JSON
브라우저 Worker -> 해석 검증: interpret.js
해석 검증 -> 상태 연산: ops.js 경계·충돌
상태 연산 -> 방·대화
해석 검증 --> 규칙 계획기: 답이 늦거나 틀리면
규칙 계획기 --> 상태 연산
```

- 모델은 의도와 동작, 가구·공간 유형, 이동할 공간을 허용 목록 값으로 고른다.
- 크기 느낌(인원·작다/크다·깊다/얕다·낮다/높다), 가구·벽·바닥 색, 다음 도구, 답 문장도 함께 돌려준다.
- 숫자 치수는 모델이 아니라 앱이 문장에서 직접 읽는다. 직접 정한 치수와 문장에서 읽은 값은 모델 단서가 바꾸지 않는다.
- 문장에 적힌 가구·공간 이름과 모델 선택이 어긋나면 문장을 따른다. 말하지 않은 속성(벽만 말했는데 바닥·공간 유형)과 문장에 없는 동작(삭제·비우기 등)은 실행하지 않는다. 바로잡은 내용은 답 아래에 펼쳐 볼 수 있다.
- 사용자 문장을 되풀이하거나, 프롬프트 예시를 베끼거나, 숫자를 말하거나, 말하지 않은 인원수를 말하는 모델 답은 쓰지 않고 앱이 만든 문장으로 바꾼다.
- 사진은 SigLIP이 20가지 가구 이름과 비교한다. 확률 70% 이상이면 그 유형의 기본 크기로 초안을 만들고 다른 후보 두 개를 칩으로 둔다. 그보다 낮으면 후보 세 개만 보여준다. 실제 사진 test 58장에서 1순위 정답 82.8%, 상위 3개 안 96.6%였다(`eval/photo/`). 사진으로 cm를 쟀다고 표시하지 않는다.

## E 지원 범위
- 가구 20종·63가지 치수 초안, 썸네일·검색·분류, 규격 비교와 들어가는지 표시
- 방 7유형·21개 크기 초안, 벽·바닥 마감, 최대 12개 독립 공간
- 2D 평면·3D 모형, 끌어 옮기기·회전·복제·삭제, 5cm 자석, 벽 경계와 겹침 표시, 되돌리기·다시 실행
- 브라우저 자동 저장(배치와 대화 글), 배치 JSON 입출력(v1~v3), PNG 저장
- WebGL이 없으면 2D, 저장소가 막히면 파일 저장 안내

각 공간은 독립된 직사각형이다. 여러 방이 이어진 주택 도면과 문·창문 편집은 없다. 사진과 대화는 배치 파일에 넣지 않는다.

## F 서버 없는 실행
추론은 WebLLM(Gemma 3 1B, f16 미지원 GPU는 Qwen3 0.6B)과 Transformers.js(SigLIP base)로 브라우저 Worker에서 한다. 처음 한 번 공개 저장소에서 모델을 내려받고, 사진과 대화는 추론 서버로 보내지 않는다. GitHub Pages에 정적 빌드를 배포한다.

공용 스킬 파이프라인: 기획(answer-me-with-html) → 구현 → unslop 디자인 점검 → humanizer 문구 점검 → 단위·브라우저 테스트·실제 모델 확인 → 커밋·푸시·배포.
