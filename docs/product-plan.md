방과 가구를 이야기하면 필요한 편집 카드가 대화에 나타난다. 카드에서 치수와 마감을 바꾸면 옆 도면에 바로 반영된다. 첫 화면은 데스크톱과 모바일 모두 상담이다.

## A 사용 흐름
```flow
설명 또는 사진 -> 상담: 방과 가구에 대한 의도
상담 -> 편집 카드: 치수·규격·유형·마감·색상
편집 카드 -> 사용자 조절: 직접 입력 또는 선택
사용자 조절 -> 2D·3D 미리보기: 같은 상태를 반영
2D·3D 미리보기 -> 다음 대화: 가구 배치 후에도 이어가기
다음 대화 -> 저장: 배치 JSON 또는 PNG
```

입력창은 하단에 남고 대화만 스크롤된다. 사진은 첨부 버튼이나 드롭으로 추가한다. 모바일에서는 도면 보기와 상담 복귀를 오갈 수 있다.

## B 필요한 도구가 나타나는 방식
| 요청 | 나타나는 카드 | 연결되는 상태 |
|---|---|---|
| 거실 가로 5m 세로 4m | 방 치수 입력 | 가로·세로·천장 높이 |
| 침실로 꾸며줘 | 공간 유형 선택 | 7가지 공간 유형 |
| 벽은 세이지, 바닥은 월넛 | 마감 선택 | 벽·바닥 색상 |
| 두 명이 앉는 소파 | 가구 규격 선택 | 유형별 치수 초안 |
| 책상 가로 120cm | 가구 치수 입력 | 가로·깊이·전체 높이 |
| 소파 색상 고르기 | 가구 색상 선택 | 배치 가구 색상 |

기본 상담은 규칙으로 도구를 선택한다. Gemma를 준비하면 모델이 구조화된 `ui` 값과 크기 단서를 반환한다. 화면에서 두 상태를 구분한다.

## C 모델과 앱의 경계
```flow
사용자 대화 -> 브라우저 Worker: 로컬 Gemma
브라우저 Worker -> 구조화 응답: 크기 단서·ui·답변
구조화 응답 -> 앱 검증: 허용된 도구와 속성만
앱 검증 -> 편집 카드: 자체 컴포넌트 렌더링
편집 카드 -> 공간 상태: 입력·색상·선택 동작
공간 상태 -> 도면: 좌표·경계·충돌 계산
```

모델이 고른 도구를 앱이 허용 목록으로 검증한다. 모델의 HTML이나 스크립트를 실행하지 않는다. 명시한 숫자는 응답 전에 반영하고, 모델 응답이 직접 입력값을 덮어쓰지 못하게 한다. 마감 요청이 방 유형·크기를 바꾸거나 요청하지 않은 가구 높이를 바꾸지 못하도록 제한한다.

사진은 SmolVLM이 보이는 종류·형태를 설명한다. 실제 cm 치수는 사진만으로 확정하지 않는다. 면적만 알려주면 현재 비율에서 가로·세로를 나눈 가정임을 알린다.

## D 지원 범위
- 가구 20종·63가지 치수 초안, 검색·분류·실제 3D 미리보기
- 방 7유형·21개 크기 초안, 벽·바닥 색상, 최대 12개 독립 공간
- 가구 이동·회전·복제·삭제, 경계·겹침 표시, 실행 취소·다시 실행
- 브라우저 자동 저장, JSON 검증·입출력, PNG 저장
- WebGL 미지원 시 2D, 저장소 차단 시 파일 저장 안내

각 공간은 독립된 직사각형 평면이다. 여러 방이 이어진 주택 도면과 문·창문 편집은 제공하지 않는다. 배치 파일에는 사진과 대화 기록을 포함하지 않는다.

## E 서버 없는 개발·배포
추론은 WebLLM과 Transformers.js로 브라우저에서 실행한다. 최초 모델·라이브러리 다운로드는 필요하며 사용자 입력을 추론 서버로 보내지 않는다. GitHub Pages에 정적 빌드를 배포한다.

Google Cloud GenUI, A2UI, Vercel AI SDK의 컴포넌트 선택·데이터 바인딩 원리를 참고했다. 자체 JSON 카드 스키마를 구현했으며 A2UI 프로토콜 호환을 주장하지 않는다.

공용 스킬 파이프라인은 기획 설명 → 구현 → unslop 디자인 검토 → humanizer 문구 검토 → 테스트 → 커밋·푸시·배포 순서다.
